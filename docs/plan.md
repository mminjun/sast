# SAST 프로젝트 계획

## 1. 이해한 요구사항 (핵심)
멘토 확인: "소스코드를 넣고 분석이 가능하도록, 분석 기능을
테스트해볼 수 있도록" → 업로드→분석→결과조회→테스트가 심장
(SFR-007~009, 014~017, TST-004~005)

## 2. 기술 스택 (+ 이유)
- 백엔드: Django + DRF — 인증/권한/관리자/ORM 내장,
  RFP 관리 요구(SFR-001~006) 빠른 구현, 검증된 보안 기본값
- 프론트: React — pen.dev 목업 활용 (탈출구: Django 템플릿)
- DB: PostgreSQL — 관계형·무결성·마이그레이션 (DAR-001, 010)
- 엔진: Semgrep — 룰 독립 관리(QLT-002), JSON 결과 (SFR-009)

## 3. Use Case (역할 설계 근거 — SFR-003)
- 관리자: 프로젝트 생성/수정, 사용자 할당, 분석 실행, 전체 조회
- 일반: 할당된 프로젝트 결과 읽기 전용
- 2역할 근거: RFP가 "최소한" 관리자/일반 요구, MVP엔 추가 역할 use case 없음

## 4. MVP 범위 (번호 매핑)
- 로그인+2역할 (SFR-001~003, SEC-002~004)
- 프로젝트 생성·조회·사용자 할당 (SFR-004~006)
- zip 업로드 (SFR-007)
- Semgrep 분석 실행 + 상태 관리 (SFR-008~009, 015)
- KISA 49개 카탈로그 등록·조회 + 일부 항목 실탐지 매핑 (SFR-013)
- 결과 표준화 저장 (SFR-014, DAR-006)
- 대시보드 조회 + 심각도 필터 (SFR-016~017)
- 핵심 보안: bcrypt(SEC-001), IDOR 방어(SEC-005),
  작업영역 격리(SEC-007), Zip Slip 방어(SEC-008)
- 데이터 6테이블: users/projects/project_users/
  analysis_runs/findings/rules (DAR-002~007, 010)

## 5. 비목표 (+ 이유)
- 49개 전부 탐지 → 일부만 (시간, 멘토 승인)
- Java·JS → Python만, 확장 구조만 (SFR-010 "구조" 요구)
- git 연계·내부경로 → zip만 (SFR-007 수행사 위임)
- 프로젝트 삭제, DAR-008 완전판 → 후순위
- SEC-006, 009 → 기본 수준 (통일 에러 응답, 타임아웃)

## 6. 결정 사항 + 근거 (멘토 "이유 필요" 대응)
- 비밀번호: bcrypt — SHA-2는 고속 해시라 무차별 대입에 취약,
  적응형 해시가 적절
- 심각도: KISA 진단가이드 취약점 유형 분류 기반으로 부여. 직접 침해·인증우회·정보유출 유형(입력값 검증·보안기능 등)은 High, 그 외 간접 영향은 Medium/Low. Semgrep 기본 severity(ERROR/WARNING/INFO)는 초기 참고값, 최종 등급은 유형 기준 확정 — QLT-004 정규화 계층에서 통일
- 인증: 이메일 ID + 방식(세션/토큰)은 설계 단계 결정
- SEC-010 계획: Semgrep 버전 고정(requirements.txt),
  라이선스 확인(LGPL 계열 — 확인 필요), 릴리즈 노트 모니터링

## 7. SAST 관점 반영 (OT 완료 기준)
- 시큐어 코딩: SEC 구현 자체 (해시·IDOR·격리·경로검증)
- 셀프 분석(도그푸딩): 완성한 SAST로 내 프로젝트 코드를
  분석해서 발표에 포함
